# 装修效果展示网站 · 需求澄清

版本：v0.8｜日期：2026-10-12｜状态：已确认并据此开发（M1、M2 已完成）｜各版变化见第 14 节

> 一句话目标：像编辑 PPT 一样搭建户型、摆放家具，也可以用对话完成相同修改，并随时查看同步更新的温馨微缩风 3D 小家。

## 1. 文档怎么用

本项目按“需求澄清 → 方案设计 → 验收清单 → 变更日志”推进。本次只编写需求，不选定具体框架、不编写网页代码，也不修改已有水杯原型。

| 阶段 | 主要回答 | 什么时候完成 |
|---|---|---|
| 需求澄清（本文） | 做什么、如何操作、哪些不做 | 主要功能和有分歧的规则得到确认 |
| 方案设计 | 数据怎么组织、模块怎么拆、如何渲染和接入模型 | 能据此实施，关键外部接口经过核实 |
| 验收清单 | 用什么操作证明功能正确 | 开发前写清标准，开发后逐项记录结果 |
| 变更日志 | 相比上一版改了什么、为什么改、影响哪里 | 从首次需求调整开始持续记录 |

本文用三种标记区分结论：**已确定**是用户明确提出或选择的要求；**草案默认**是为便于推进而提出的可调整规则；**待确认**是不能擅自定死的问题。功能编号用于连接后续方案、测试和变更记录，不代表已经实现。

## 2. 已确定的方向

| 项目 | 结论 |
|---|---|
| 使用者 | 个人使用，面向开发新手；页面和文档以清楚易懂的中文为主 |
| 户型来源 | 手动绘制，或通过对话创建、调整；可上传户型图照片由 AI 识别成初稿再核对（AI-11），不承诺与原图精确一致 |
| 两个页面 | 平面户型图、3D 效果图；每页都有预览和编辑模式 |
| 两个编辑维度 | 房间维度、家具维度；墙、门、窗归入房间维度 |
| 房间形状与尺寸 | 只做横竖对齐的矩形，首版不能旋转；L 形用两个矩形拼、中间不建墙；长宽按墙中心线（轴线尺寸）计算 |
| 门类型 | 用途（入户门／室内门）+ 开启方式（平开／移门／无门扇）；不设“推拉门”选项 |
| 编辑入口 | 大模型对话和手动操作；两者执行相同的修改规则 |
| 3D 展示效果 | 使用温馨微缩模型的呈现方式，参考 photo-to-cozy-home 的视觉方向；整栋房子放在一个巨大的方块展示基座上；单间展示时只显示这一间，放在按房间大小生成的小展台上；不追求照片级效果 |
| 室内装修风格 | 保留温馨浅木默认方案，增加“简约中古风”：白色为主、胡桃木色为辅；支持自定义整体配色和基础材质 |
| 3D 手动操作 | 点选对象，再通过参数面板修改；首版不要求在 3D 中直接拖拽变换 |
| 模型服务 | 默认 DeepSeek，同时支持百炼、GLM、OpenAI（GPT 系列）及可扩展的其他服务 |
| 保存与迁移 | 本地保存；设计和相关资源可以一起带到另一台电脑继续使用 |
| 历史版本 | 可以回退到较早保存的版本；导出时只带当前设计，不带历史版本 |
| 可维护性 | 各功能分开组织，替换模型服务、调整家具或修改页面时，尽量不影响其他模块 |

### 2.1 首版暂不纳入

不做云端多人协作，以及不要求 3D 直接拖拽，来自本次已确认的选择；自动识图曾属已确认的排除项，在 v0.8 按用户新决定纳入（AI-10～12）。其余排除项是控制首版工作量的**草案默认**，仍可调整：

- 登录、云同步、多人同时编辑、公开发布与在线分享权限。
- 保证与照片精确一致的自动还原（图片识别只到“可用初稿”，见 AI-11）、任意曲线或斜墙、多楼层、楼梯和屋顶设计。
- 人物行走、家具生活动画、昼夜天气系统；参考项目有这些功能，不代表本项目需要照搬。
- 照片级出图、真实日照计算、自动生成任意家具模型、施工图和工程量报价。
- 手机上的完整编辑体验；草案默认先做好电脑浏览器，手机只列为后续适配方向。

这些排除项不影响首版已有的房间、门窗、家具编辑与 3D 展示。后续新增能力需记录需求变化，不能顺手扩大范围。

## 3. 页面、模式和基本操作

### 3.1 两个页面共用一个设计

平面图和 3D 不是两份独立的设计稿，而是同一套房屋数据的两种看法。任一页面修改后，另一页面应立即反映相同结果；切页不清空设计，也不重置聊天。

草案默认布局：左侧对话栏、中间画布、右侧对象与参数面板；顶部切换页面、模式和编辑维度。对话栏和参数面板可收起，给画布留出空间。具体排版放到方案阶段确认。

| 功能编号 | 区域 | 预览模式 | 编辑模式 |
|---|---|---|---|
| PAGE-01 | 平面户型图 | 查看房名、尺寸、墙、门窗和家具；缩放、平移、点选查看信息 | 绘制房间，移动、调整大小、复制、删除；编辑墙门窗和家具 |
| PAGE-02 | 3D 效果图 | 旋转、缩放、查看全屋或单房间；切换完整墙体与剖面 | 保留查看操作；点选房间、墙面、门窗或家具，通过参数面板修改 |
| PAGE-03 | 对话栏 | 默认可收起；可以提问、让 AI 调整视角；修改要求以“试看”显示，点“应用到设计”时先切到编辑模式再写入 | 可以提出设计修改，同样先试看、再应用，并查看修改前后的说明 |
| PAGE-04 | 房间／家具维度切换 | 可筛选查看对象 | 房间维度优先选择房间及墙门窗；家具维度优先选择家具，避免误操作 |

草案默认：预览／编辑模式和房间／家具维度是全局设置，切换平面与 3D 页面时保持不变；选中的对象也一起保留，切页后在另一页仍高亮同一对象。

“剖面”指暂时隐藏或降低挡住视线的墙，方便看内部；它只改变显示，不删除墙，也不改变房间尺寸。

“预览”是页面模式，表示只看、不直接修改；“试看”是一份尚未应用的候选修改，看起来改了，实际设计没变。两个词刻意区分，设计所处的几种状态见第 3.3 节。

### 3.2 共用编辑规则

两种编辑共用底层规则已确定。以下选择提示、撤销重做、提交与失败处理是**草案默认**，用于把操作过程说清楚，不代表用户已逐条确认。

| 功能编号 | 要求 |
|---|---|
| EDIT-01 | 点选对象后高亮，并显示对象名称、类型和可修改项目；无选中对象时给出操作提示 |
| EDIT-02 | 手动修改和 AI 修改都必须检查尺寸、位置、对象是否存在等规则；不能一边允许、一边禁止 |
| EDIT-03 | 提供撤销、重做；一次完整拖动算一步，一次应用的试看方案（AI 修改或风格批量修改）算一步，不把每个拖动像素记为一步；试看和放弃不产生撤销记录 |
| EDIT-04 | 无效输入说明原因并保留原值，不把错误值悄悄改成另一个数字；显示值必须与实际设计一致 |
| EDIT-05 | 删除对象、清空设计及替换当前项目时，说明影响并要求确认；取消后保持原状 |
| EDIT-06 | 同一批修改要么全部成功，要么全部不执行，避免一半家具改了、一半没改 |

草案默认：手动参数通过回车或离开输入框提交，拖拽在松手时提交；AI 修改和风格批量修改先试看，点击“应用到设计”才写入。预览模式本身从不写入设计：在预览中点击“应用到设计”时，程序先切换到编辑模式，再执行应用（见 TRY-07），所以“预览只看不改”始终成立。

### 3.3 设计的四种状态

“应用”“保存”“试看”容易混用，草案默认把设计分成四种状态：

| 状态 | 含义 | 会写入本地存储吗 | 能否导出 |
|---|---|---|---|
| 当前设计 | 已经应用、正在使用的设计；所有页面以它为准 | 会，自动保存；保存进度单独显示为“未保存／保存中／已保存／失败” | 能 |
| 试看方案 | 当前设计加上一组尚未应用的候选修改 | 不会 | 不能，需先应用或放弃 |
| 历史查看 | 正在查看某个历史版本，当前设计保持不变 | 不会 | 不能，需先恢复或退出查看 |
| 已保存设计 | 最近一次成功写入本地的当前设计；刷新后恢复的就是它 | 它本身就是本地副本 | 导出时使用当前设计 |

“应用”是把试看方案写进当前设计；“保存”是把当前设计写进本地存储。应用后通常很快会自动保存，但两者不是同一件事，界面不能把“已应用”显示成“已保存”。

试看方案和历史查看同一时间只能存在一个。处于这两种状态时，导入、导出和“保存为版本”暂不可用，并提示用户先处理。

## 4. 房间维度

### 4.1 房间矩形

房间以矩形表达，支持像 PPT 一样在画布中创建和调整。首版矩形与画布横竖方向对齐，**已确定不提供房间旋转**；任意角度和不规则房间暂不纳入。

- **不做房间旋转的原因：**对空房间来说，转 90° 只等于交换长和宽；但旋转会让“长是左右方向”“起点是左上角”这些定义跟着变化，容易填错。首版先保持定义稳定。
- **L 形等非矩形空间（已确定）：**用两个相邻的矩形房间拼出，二者之间设为开放、不建墙（WALL-04）；平面上各自显示名称和尺寸。

| 功能编号 | 可编辑项目／操作 | 说明 |
|---|---|---|
| ROOM-01 | 创建、选中、移动、复制、删除 | 拖出矩形创建房间，也可输入具体数值；复制品需放到不与现有房间重叠的位置 |
| ROOM-02 | 长、宽 | 草案默认“长”为平面左右方向，“宽”为上下方向；面板配方向示意，避免只写数字 |
| ROOM-03 | 起点位置 | 房间矩形（墙中心线）左上角相对画布原点的位置；向右、向下为正，允许输入坐标 |
| ROOM-04 | 房间属性 | 名称、用途、平面识别色；用途如客厅、卧室、厨房、卫生间、阳台、其他 |
| ROOM-05 | 拖动变换 | 拖动边或角改变长宽；支持网格与边缘吸附、对齐参考线，并可临时关闭吸附 |
| ROOM-06 | 地面外观 | 草案默认支持地面颜色和基础材质，平面识别色不强制等于 3D 地面颜色 |
| ROOM-07 | 名称与尺寸标注 | 画布上显示房名和长宽；缩小时不让大量文字完全遮住房间 |

尺寸统一以毫米作为编辑基准，可把 4000 mm 显示为 4.00 m；屏幕缩放只改变看起来的大小，不改变实际尺寸。

**尺寸口径（已确定：墙中心线）：**

- **长宽按墙中心线算：**房间矩形的四条边就是四面墙的中心线，墙厚从中心线向两边各展开一半。这样填写简单，相邻房间直接共用一条边。代价是显示的长宽比实际室内大，大出的部分是两侧墙厚的一半之和。例如长 4000 mm、两侧墙厚都是 240 mm 时，室内净长 = 4000 − 120 − 120 = 3760 mm。
- **标注写清口径：**画布和参数面板把长宽标为“轴线尺寸”，不冒充室内净尺寸。草案默认在参数面板另外显示程序算出的“室内净尺寸（参考）”，只读，方便判断家具放不放得下。
- **两间房相邻：**两个房间矩形共用同一条边，这条边就是共用墙的中心线；吸附功能会自动对齐到这条边。
- **修改墙厚度：**墙中心线位置不动，墙向两侧同时变厚或变薄，房间的轴线尺寸和位置都不变，只有室内净尺寸随之变化。变厚后如果家具或门窗碰到墙，按第 4.2 节先标出冲突，解决后才能提交。

### 4.2 房间与家具的关系

“相对独立”是指可以单独管理和修改，不是取消空间关系。家具属于某个房间，门窗属于某段墙，必须能追踪这些关系。

草案默认规则：

- **移动房间：**所属家具跟随整体移动，保持在房间内的相对位置；墙和门窗同步更新。
- **调整房间大小：**不自动拉伸家具。若家具或门窗放不下，先标出冲突，解决后才能应用这次修改。
- **修改房间名称或用途：**不改几何、不替换家具。例如“卧室”改叫“书房”，不等于自动把床换成书桌。
- **移动家具：**不反向移动房间或墙。需要跨房间时明确选择目标房间，并重新检查位置。
- **删除房间：**提示将删除的所属家具、专属墙和门窗；不删除其他房间仍在使用的共用墙。一次撤销能恢复整组对象。
- **房间重叠：**首版不允许两个房间有重叠面积；允许共边或局部共边，也允许不相邻。

## 5. 墙、门、窗

### 5.1 墙体

墙沿房间矩形的边自动生成，不另起一套自由绘墙工具，也不能单独移动墙或改墙长；想改墙的位置和长度，就改房间。相邻房间共用同一段墙，不能生成两堵重叠的墙；局部相邻时按实际相邻范围处理。

| 功能编号 | 可编辑项目 | 说明 |
|---|---|---|
| WALL-01 | 所属边与范围（只读） | 由房间位置自动算出，不能直接修改；显示位于哪个房间的哪条边，共用墙显示两侧房间名称 |
| WALL-02 | 厚度、高度 | 改厚度或高度后，平面与 3D 同步；厚度必须大于 0，高度需容纳已有门窗；改共用墙厚度的规则见第 4.1 节 |
| WALL-03 | 墙面颜色 | 共用墙允许两侧不同颜色；面板按“客厅侧”“卧室侧”区分，避免颜色改错面 |
| WALL-04 | 整段开放 | 草案默认允许指定某条边整段不建墙，用于开放客餐厅；原来墙所在的位置按地面连接显示。只开一部分时，在墙上放一个“无门扇”的门（见 DOOR-01），不另设第二种表达方式 |

调整共用墙要提示影响两个房间。房间移动导致不再相邻时，重新检查共用关系；原有门窗尽量保留绑定位置，无法明确归属时提示选择，不自动丢弃。

### 5.2 门

门由“墙上的开口”和“装什么门”两部分组成。“入户门”说的是用途，“移门、无门洞”说的是开合方式，所以门类型用两个字段来编辑。**已确定删除“推拉门”选项**，左右滑动的门统一叫“移门”。

| 功能编号 | 可编辑项目 | 说明 |
|---|---|---|
| DOOR-01 | 类型：用途 + 开启方式 | 用途分为入户门、室内门，入户门只能放在外墙（只有一侧有房间的墙）上。开启方式分为平开、移门、无门扇；原要求中的“无门洞”按“只留门洞、不装门”理解，即“无门扇”。普通平开门是草案补充 |
| DOOR-02 | 所在墙与墙上位置 | 选中墙后放置；位置指洞口起点距墙参考端的距离，画布显示参考端和方向箭头 |
| DOOR-03 | 宽、高 | 指洞口尺寸；门必须完整落在墙段内，不能超出墙顶或墙端 |
| DOOR-04 | 颜色 | 修改门扇／门框颜色；无门扇时不显示门扇颜色 |
| DOOR-05 | 开门方向 | 平开门区分铰链侧和开向哪个房间；移门标明滑动方向；无门扇不设开门方向 |

平面图显示门洞及必要的开启方向，3D 显示对应开口和门的造型。首版需要正确表达开门方向，但不要求人物使用门、自动避让或精细门扇动画。入户门同样可以选平开或移门。

### 5.3 窗

| 功能编号 | 可编辑项目 | 说明 |
|---|---|---|
| WIN-01 | 类型 | 落地窗、普通窗；原描述中的“普通床”暂按“普通窗”理解 |
| WIN-02 | 所在墙与墙上位置 | 与门使用相同的墙参考端和距离口径 |
| WIN-03 | 宽、高、离地高度 | 普通窗可设窗台高度，落地窗默认接近地面；不能越出墙段或墙顶 |
| WIN-04 | 外观 | 草案默认可改窗框颜色；玻璃使用统一基础效果，不做玻璃工程选型 |

门窗必须形成真实的墙体开口，不能只在墙上贴一张图片。检查同一墙上的洞口是否相互重叠；无法放置时显示原因，不允许静默穿插。

## 6. 家具维度

家具可以独立选择、增删和修改，但需要知道属于哪个房间。更换家具类型或外观，不应要求重写房间编辑功能。

| 功能编号 | 可编辑项目／操作 | 说明 |
|---|---|---|
| FURN-01 | 添加、复制、删除、改名 | 从基础家具列表选择并放入房间；新增后必须有可识别的名称和类别 |
| FURN-02 | 大小 | 长、宽、高；可以输入数值，平面页可拖动调整占地大小 |
| FURN-03 | 位置 | 所属房间、相对房间的平面位置、离地高度；平面位置草案默认以家具底面中心表示，并显示锚点 |
| FURN-04 | 朝向 | 平面旋转角度；手动与 AI 使用同一方向定义 |
| FURN-05 | 颜色与材质 | 基础纯色、木质、布艺、金属、玻璃等预设；有多个部件时明确修改整件还是某一部分 |
| FURN-06 | 平面与 3D 表达 | 平面有可识别的轮廓和朝向，3D 有对应造型；二者占地、尺寸、位置一致 |

草案建议首批家具：床、衣柜、沙发、茶几、电视柜、餐桌、椅子、书桌、基础橱柜。具体造型数量和素材来源在方案阶段确定，不承诺无限家具库。

不是所有家具都适合任意材质或任意拉伸。每个家具模板需列明支持的参数；不支持的修改应解释原因，不能显示“已成功”但画面不变。复制家具使用新身份，修改复制品不能连带修改原件。

位置检查分两级：穿过实体墙或明显放出房间属于错误，不能提交；家具之间的重叠先给提示，不一概禁止，因为椅子可以部分放进桌下，地毯可以位于桌子下方。首版不做完整物理模拟。

## 7. 大模型对话与统一修改

### 7.1 用户怎么操作

例：“把客厅改成长 5 米、宽 4 米”“把选中的沙发向左移 20 厘米”“把卧室这面墙改成浅米色”；也可以给消息附带图片，让 AI 照图搭户型、配家具或定风格（AI-10、AI-11）。AI 需要结合当前设计和选中对象理解，而不是只看一句孤立的话。

AI 的回复分三类，预览和编辑模式都能使用对话栏：

| 输出类型 | 例子 | 是否改变设计 | 预览模式 | 编辑模式 |
|---|---|---|---|---|
| 回答 | “客厅多大？”“这面墙放得下 2 米沙发吗？” | 否 | 可以 | 可以 |
| 视图操作 | “带我看主卧”“切到俯视”“把选中的沙发标出来” | 否，只改变看的角度、高亮和所在房间 | 可以 | 可以 |
| 设计修改 | “沙发换成灰色”“客厅加宽 30 厘米” | 应用后才改变 | 可以试看；应用时先切到编辑模式再写入 | 试看后应用 |

设计修改的流程：

1. 用户选择对象，或在文字里说清目标；预览、编辑模式均可发起。
2. AI 提出具体修改；目标不明确时先问，例如“你说的是主卧还是次卧？”
3. 系统用与手动编辑相同的规则检查整组修改，列出改了谁、哪些字段、旧值和新值；不通过时不进入试看，只说明原因。
4. 检查通过后进入**试看**：平面和 3D 显示修改后的效果，并明确标出“试看中，尚未应用”。
5. 用户选择“应用到设计”“放弃”或“继续调整”（规则见第 7.2 节）。应用后平面和 3D 一起按新设计显示；放弃则恢复原样。
6. 系统把实际执行结果反馈给 AI，由 AI 说明已应用、已放弃、失败或仍需确认的事项。

这里的 AI 负责理解和提出修改，浏览器中的渲染程序负责画出模型。不是每次对话重新生成一张房屋图片。试看时，程序把修改叠加到当前设计上得到一份临时的候选设计，再交给同一个渲染程序显示，不另做一套画法。

### 7.2 试看：先看效果，再应用到设计

以下规则是**草案默认**，用户已同意“预览中保留 AI 入口、修改以试看方式呈现”这一方向，细节仍可调整。

试看不只用于 AI：风格切换等一次影响很多对象的手动批量修改（STYLE-05）也走试看。普通的单项手动修改（改一个数值、拖动一次）直接提交，不经过试看。

| 功能编号 | 要求 |
|---|---|
| TRY-01 | 只有整组修改生成完毕并通过规则检查后，才一次性显示试看效果；生成期间只显示“正在生成方案”，不边生成边画，避免画面闪动或出现门悬在墙外等中间状态 |
| TRY-02 | 试看中显示醒目提示“试看中，尚未应用”；平面图用虚线或高亮标出改动位置，3D 提供“修改前／修改后”切换 |
| TRY-03 | 三种选择：**应用到设计**写入当前设计，记为一个可撤销步骤，并进入自动保存；**放弃**恢复原样，不留下任何记录；**继续调整**在当前试看结果上继续修改（AI 试看继续对话，风格试看继续调参数），再次检查后更新试看 |
| TRY-04 | 试看内容不进入自动保存、导出文件和撤销记录；刷新页面或关闭程序时试看内容丢弃，只保留已应用的设计 |
| TRY-05 | 切换平面／3D 页面时保留同一份试看结果，两页都显示相同提示，不能一页是新效果、另一页是旧效果 |
| TRY-06 | 试看期间若用户在编辑模式手动改了相关对象，按 AI-07 在应用前重新检查；冲突时提示重新生成，不直接覆盖手动修改 |
| TRY-07 | 在预览模式点击“应用到设计”时，先切换到编辑模式，再执行应用；保持当前页面和视角，方便继续调整。预览模式本身不写入设计 |
| TRY-08 | 同一时间只有一份试看；试看中不能再发起另一份试看、查看历史版本、导入或导出，需先应用或放弃（与第 3.3 节一致） |

用数据库来类比：试看是在事务里改完先查看结果，尚未 `COMMIT`；应用是 `COMMIT`；放弃是 `ROLLBACK`。

### 7.3 必须遵守的规则

| 功能编号 | 要求 |
|---|---|
| AI-01 | 页面提供聊天记录、输入框、发送、等待提示和明确的错误提示；等待期间避免重复提交 |
| AI-02 | 每轮使用当前设计和选中对象作为依据；切换模型服务后仍以当前设计为准 |
| AI-03 | AI 和手动编辑经过同一个修改入口，使用相同的对象、字段、限制与撤销记录 |
| AI-04 | AI 只可提出支持的设计操作；未知字段、任意脚本或 HTML 不得直接执行 |
| AI-05 | 正确回传实际执行结果；失败、放弃、尺寸不合法时，不允许声称已经修改；试看中也不能说成已应用或已保存 |
| AI-06 | 多个对象的一次修改作为一组应用，并可一次撤销；部分不合法时整组不写入 |
| AI-07 | AI 等待或试看期间若用户手动改了相关设计，原建议不能盲目覆盖新值；应用前重新检查，必要时重新生成建议 |
| AI-08 | 回答和视图操作不改变设计；“随便改得好看点”等范围不明确的请求先形成建议，而不是任意重做全屋 |
| AI-09 | 对话记忆：模型本身不记事，每轮由程序把最近若干轮对话和最新的当前设计一起发给模型；数量在方案阶段按模型可接收的长度确定。更早的对话不再发送，因此模型可能忘记很久以前说的话；设计内容始终以每轮附带的当前设计为准，不依赖模型记忆。刷新页面后聊天记录不恢复（见第 9 节） |
| AI-10 | 图片上传：对话栏可给消息附带图片（户型图、家具或风格参考照）；格式与大小上限在方案阶段确定。图片只随聊天存在于内存，不进自动保存、历史版本和导出包，刷新后与聊天记录一同丢弃 |
| AI-11 | 三个识别方向：①户型图——AI 读图提出房间与门窗的修改指令，作为**初稿**走试看，尺寸优先读图上标注、无标注时估算，用户核对调整；②家具——AI 参考图片添加或调整家具，只能映射到内置家具模板，没有对应模板时说明原因，不凭空生成新模型；③风格——AI 参考图片提出配色与材质修改，只改风格系统支持的兼容外观（STYLE-04），不因此改动几何或增删家具 |
| AI-12 | 当前所选服务或模型不支持图片输入时，明确提示原因，不静默忽略；各家可用的视觉模型在开发中实测确认（同 MODEL-02） |

首版 AI 的能力范围就是已实现的房间、墙门窗、家具编辑能力。图片识别不扩大这个范围：它只是给模型多一种输入，输出仍是上述能力内的修改指令（AI-11）。增加全新对象类型仍需补充程序和验证规则，不能认为换个提示词就一定可用。

### 7.4 模型服务设置

| 功能编号 | 要求 |
|---|---|
| MODEL-01 | 默认提供 DeepSeek 选项，并提供百炼、GLM、OpenAI 配置入口；可切换服务地址、模型名称和 API Key（调用密钥） |
| MODEL-02 | 不把某个具体模型名称永久写死；方案阶段核实各服务当时可用的接口、模型和结构化修改能力 |
| MODEL-03 | 提供“测试连接”，只在用户点击时发请求，不因打开设置或切换选项自动消耗额度 |
| MODEL-04 | 说明缺密钥、鉴权失败、模型不存在、不支持所需能力、超时或网络问题；失败不破坏当前设计 |
| MODEL-05 | 界面使用统一设置方式，但不假定所有厂商接口完全相同；以后增加服务不应修改户型和渲染模块 |

AI 请求会把用户输入（含附带的图片）、当前设计和完成任务所需的设计信息发送给所选服务。设置处要明确提示；不自动上传整个项目资源包。服务侧的数据使用与保留政策需以各厂商实际条款为准。

## 8. 3D 展示目标

**已确定：使用温馨微缩模型的展示方式。**微缩感来自俯看视角、展示基座、柔和光影和适度圆润的模型表现，不绑定某一套室内配色。室内装修风格另由第 8.2 节管理；切换风格不应任意改变用户输入的房间、门窗或家具尺寸。

| 功能编号 | 要求 |
|---|---|
| VIEW-01 | 拖动旋转、滚轮缩放、恢复视角、俯视；控制镜头不改变设计尺寸 |
| VIEW-02 | 全屋与单房间切换；单房间的展示方式见第 8.3 节，仍读取同一份设计，不复制另一份独立场景数据 |
| VIEW-03 | 完整墙体／剖面切换；墙上门窗与显示效果同步，不出现墙隐藏了、门窗悬空的明显错误 |
| VIEW-04 | 房间、墙、门窗、家具均与平面数据对应；修改颜色、材质、大小和位置后更新可见效果 |
| VIEW-05 | 进入某房间、改变画布空间或明显改变房屋大小时合理取景；不每帧抢回用户手动调整的视角 |
| VIEW-06 | 出现加载失败或浏览器不支持 3D 时，显示原因并允许继续查看平面图，不只留白屏 |
| VIEW-07 | 整栋房子下方显示一个巨大的方块形展示基座，像微缩模型的台子；基座完整承托全屋，使房屋在 3D 中有清楚的展示边界和悬浮展品感 |
| VIEW-08 | 提供室内风格选择和自定义设置；更换风格通过统一修改入口先试看再应用，平面与 3D 使用同一套颜色和材质数据 |

### 8.1 展示基座

展示基座是 3D 视觉部件，不是房间、地板或家具，也不参与住宅面积、墙高、家具离地高度和碰撞计算。平面户型图不绘制基座，避免把装饰误认为房屋结构。

**已确定：**整栋房子下方需要一个巨大的方块作为基石展示。以下细节是**草案默认**：

- 基座为低矮的长方体，水平覆盖整个房屋；四周根据全屋外轮廓自动留出一致的展示边距。房屋尺寸变化时，基座随整体外轮廓更新，不需要手动跟着调整。
- 基座顶面位于房屋地面下方，不能穿进地板、墙体或家具；它不改变房屋自身的坐标和尺寸。
- 默认使用与温馨微缩风相符的奶油色或浅木色、轻微圆角和柔和阴影；具体高度、边距、圆角、颜色和材质在方案阶段定稿。
- 全屋视图和剖面视图中保留大基座，保证空间参照稳定；单房间视图改用按该房间大小生成的小展台（第 8.3 节），不在大基座上留下其他房间的重复模型。
- 相机自动取景需要把基座纳入画面范围，但房屋仍是主体，不能因基座过大导致房间看不清。
- 基座参数属于展示设置，随当前设计保存和导出；不进入房间／家具维度，也不允许 AI 把它误当成房间结构修改。

### 8.2 室内风格与自定义

“温馨微缩风”描述房子如何像模型一样被展示；“简约中古风”描述房子内部使用什么颜色、材质和陈设气质。两者可以同时存在，不是二选一。

**已确定：**增加“简约中古风”，以白色为主、胡桃木色为辅，并支持自定义。以下操作细节是**草案默认**：

| 功能编号 | 要求 |
|---|---|
| STYLE-01 | 内置至少两套方案：现有温馨浅木默认方案，以及简约中古风；选择预设后仍可继续自定义，不把预设锁死 |
| STYLE-02 | 简约中古风以白色墙面和大面积中性色为主，胡桃木用于柜体、桌面、门或局部家具；避免全屋大面积深木色导致画面沉重，可用少量黑色或古铜色作点缀 |
| STYLE-03 | 自定义面板至少支持主色、辅助色、点缀色、墙面颜色、地面基础材质、默认木色、金属色，以及整体灯光色温和亮度 |
| STYLE-04 | 风格修改只改变兼容对象的颜色、材质和灯光默认值，不改变房间长宽、墙高、门窗位置、家具大小与位置，也不凭风格名称自动增删家具 |
| STYLE-05 | 切换预设或应用自定义方案视为一次批量修改：先列出受影响对象并试看，用户点击“应用到设计”后才写入，且可一次撤销 |
| STYLE-06 | 草案默认保留用户已经单独修改过的对象外观；界面另提供“覆盖所有兼容对象”的明确选项，选中后才批量覆盖，并在试看中标出影响范围 |
| STYLE-07 | AI 和手动界面使用同一套风格字段和应用规则；例如“全屋改成简约中古风，墙保持暖白”必须生成可检查的结构化修改，不能只改变提示词或口头声称完成 |
| STYLE-08 | 风格预设、自定义值及对象覆盖关系随当前设计自动保存、进入历史版本并随当前设计导出；API Key 和聊天记录仍按原规则排除 |

首版“自定义”指在已有模型和材质能力范围内调整颜色、基础材质与灯光，不等于根据任意文字自动生成全新家具模型或无限纹理。可选色值、材质样例和灯光范围在方案阶段确定。

不承诺照片级材质、工程级照明或施工精度。渲染示例是视觉参考，不代表已有代码或已实现质量。

### 8.3 单房间展示

用户希望每间房能像[主卧参考图](references/cozy-home-bedroom.jpg)那样单独拿出来展示。**已确定：**单间视图只显示这一间，放在按房间大小生成的小展台上；全屋视图仍用大基座。以下细节是**草案默认**：

- 进入单房间视图后，只显示这一间的地面、墙、门窗和家具，放在一个按该房间外轮廓生成的小展台上；其他房间暂时不显示。
- 默认使用剖面效果：靠近镜头的墙降低或隐藏，方便看到室内，遵守 VIEW-03 的门窗同步规则。
- 小展台和全屋大基座同属展示设置，使用同一套颜色与材质，尺寸随房间自动变化，不参与面积和碰撞计算，平面图不绘制。
- 提供房间列表或“上一间／下一间”切换，可随时回到全屋视图；切换时镜头自动取景到该房间（VIEW-05）。
- 单房间视图读取的仍是同一份设计。在这里修改家具或墙面，回到全屋或平面图时立即看到相同结果。
- 共用墙只显示本房间一侧的颜色；门窗洞口照常显示，相邻房间不显示。

## 9. 保存、导出与换电脑

“保存设计”和“保存模型服务密钥”是两回事。前者要能备份和迁移，后者不能混进共享文件。

本地保存并携带完整资源到另一台电脑是已确定目标。自动保存、刷新恢复、导入确认及以下具体保存方式是**草案默认**，建议一起纳入首版，避免只做到“能导出”却容易丢失修改。

| 功能编号 | 要求 |
|---|---|
| SAVE-01 | 本地自动保存已应用的有效设计（不含试看内容），显示“未保存／保存中／已保存／失败”；正常刷新后可恢复最近保存成功的状态 |
| SAVE-02 | 自动保存失败时保留当前内存中的设计，提示原因，并提供导出备份，不谎报成功 |
| SAVE-03 | 导出完整项目包，包含当前设计的房间、墙门窗、家具参数、室内风格、自定义配色、展示基座设置，以及该设计用到的资源清单；程序内置的家具和材质按编号与版本引用，不重复打包；不包含历史版本；不能只有当前电脑有效的文件路径 |
| SAVE-04 | 导入时检查格式版本、数据合法性和资源是否齐全；预览项目摘要后再确认替换，不静默覆盖当前设计 |
| SAVE-05 | 在另一台电脑使用兼容的网页程序导入项目包后，可继续预览和编辑；房屋尺寸、颜色、材质和位置应一致 |
| SAVE-06 | 提供可携带的程序资源和简短启动说明；电脑需要浏览器及说明中列出的运行环境，不承诺任何系统双击单个 HTML 都能运行 |
| SAVE-07 | 设计包不包含 API Key；聊天记录草案默认不随包导出，避免把私人对话或误贴的密钥带走 |

**项目包与程序的分工：**项目包是“这套设计”，程序资源是“打开设计的软件和内置家具库”。换电脑时两样都要带上；导入时如果内置资源的版本对不上，按下文列出缺失项。

**离线范围：**程序和项目资源准备齐全后，不调用 AI 也能手动编辑、查看平面和 3D；AI 对话仍需联网并使用接收方自己的密钥。缺少资源时列出缺失项，不能悄悄换成不同家具。

草案默认不要求恢复撤销栈或刷新前的完整聊天；恢复的是已经保存成功的设计。需要回到较早的方案时，使用第 9.1 节的历史版本。浏览器本地存储可能被清理，自动保存不能替代导出备份。

**密钥安全：**首版不默认长期保存密钥；如提供“记住密钥”，需明确保存位置和风险。程序资源、设计导出、日志及截图不得自动包含密钥。是否需要本地转发服务解决跨域与密钥使用问题，在方案阶段核实，不能默认各厂商都允许浏览器直连。

### 9.1 历史版本

撤销／重做用于退回刚才的几步，刷新后不保留；历史版本用于回到较早的某个方案，刷新和重开程序后仍在。两者分开，互不替代。

**已确定：**提供历史版本回退功能；导出项目包时只带当前设计，不带历史版本。以下具体做法是**草案默认**。

| 功能编号 | 要求 |
|---|---|
| VER-01 | 手动“保存为版本”：可填写名称（如“客厅方案A”），自动记录保存时间和一张缩略图；未填名称时按时间命名 |
| VER-02 | 自动版本：在应用试看方案（AI 修改或风格批量修改）、删除房间、清空设计、导入项目替换当前设计之前，自动保存当前设计为一个版本，并注明触发原因；自动保存失败时提示，并让用户决定是否继续该操作 |
| VER-03 | 版本列表按时间排列，显示名称、时间、手动／自动和缩略图；可改名、删除，删除需确认 |
| VER-04 | 可先查看某个版本的平面和 3D 再决定是否恢复；查看时显示“正在查看历史版本，尚未恢复”，不写入当前设计。只借用试看的显示方式（改动标注、前后切换），按钮不同：只有“恢复此版本”和“退出查看”，不能在历史版本上继续修改。存在未处理的试看时，需先应用或放弃 |
| VER-05 | 恢复前先把当前设计自动保存为一个版本，再整体替换为所选版本；恢复算一次修改，可撤销，并进入自动保存。在预览模式恢复时，与 TRY-07 一样先切到编辑模式再恢复 |
| VER-06 | 版本只保存已应用的设计，不包含试看内容、撤销记录、聊天记录和 API Key |
| VER-07 | 数量控制：自动版本只保留最近 20 个，超出时删除最旧的自动版本；手动版本不自动删除。本地空间不足时提示清理，不静默丢弃手动版本 |
| VER-08 | 历史版本只保存在本机。导出项目包只包含当前设计（与 SAVE-03 一致）；在另一台电脑导入后，从这份当前设计开始积累新的版本 |

版本也存放在浏览器本地存储中，同样可能被清理。要长期保留某个重要方案，仍需切到该版本后导出备份。

## 10. 功能独立，但数据一致

模块独立是为了易改，不是要求模块彼此毫无联系。共用的数据规则必须有统一入口，不能让平面、3D、手动、AI 各维护一套。

| 功能边界 | 负责什么 | 后续修改时应避免影响什么 |
|---|---|---|
| 房间管理 | 房间矩形、属性与归属关系 | 模型厂商设置 |
| 墙门窗管理 | 共用墙、墙面和洞口 | 聊天界面 |
| 家具管理 | 家具模板、参数、资源和归属 | 房间画布工具 |
| 统一修改规则 | 检查、应用、撤销、重做 | 不绑定某一家 AI 服务 |
| 平面展示与编辑 | 画布、拖动、标注、选择 | 不自行保存另一份设计 |
| 3D 展示与编辑 | 房屋模型、全屋基座与单间展台、室内风格与自定义材质、相机、点选 | 不自行猜测房间与家具位置；基座和风格设置不混入房屋几何结构数据 |
| 对话与模型接入 | 理解请求、提出修改、反馈结果 | 不直接绕过规则修改对象 |
| 保存与迁移 | 自动保存、历史版本、导入导出、资源打包 | 不依赖模型服务是否可用 |

这是需求层面的职责划分，不是提前指定目录、类名或技术框架。具体实现由下一阶段方案设计决定。

## 11. 关键质量要求

以下是根据项目目标提出的**草案质量标准**，不是已经通过的验收结果；涉及新增能力的部分需随首版范围一并确认。

- **看得懂：**标签写清单位、方向、对象名称；错误说清“哪里不对、怎么改”，不只给英文代码。
- **结果一致：**同样的修改，从 AI 或手动进入，平面与 3D 得到相同结果；失败、放弃、预览模式和试看都不能误写设计。
- **不轻易丢数据：**刷新恢复、保存失败提示、导出迁移和导入确认是首版必要能力，不留到以后再补。
- **操作顺畅：**常见住宅规模下，拖动、缩放和参数修改不出现持续卡顿；具体房间数、家具数、测试电脑和响应指标在方案阶段确定，不能空口承诺帧率。
- **可维护：**支持新增家具或模型服务，不要求同时重写两页和两套编辑方式。
- **有使用边界：**尺寸和布局用于装修展示，不能作为承重判断、消防合规、结构安全或施工依据。

后续验收清单必须至少覆盖：双页同步（含模式、维度和选中对象跨页保留）、预览不直接写入、试看不写入（含刷新、导出、撤销、切页）、四种设计状态互斥（试看与历史查看时导入导出不可用）、两种编辑等价、轴线尺寸与共用墙（含改墙厚后室内净尺寸变化与冲突提示）、门窗越界、家具冲突、AI 失败／过期建议、撤销重做、刷新恢复、展示基座随全屋尺寸更新且不改变结构数据、单间展台与全屋数据一致、简约中古风及自定义样式只改变兼容外观且先试看、历史版本的保存与恢复（含恢复前自动留底、导出不带版本）、图片识别三方向（户型图初稿走试看、家具映射内置模板、风格只改兼容外观、不支持图片时明确提示）以及另一台电脑的完整导入。这里只定义检查方向，不声称已经测试通过。

### 12.1 首版开发顺序（草案）

首版功能较多，建议按依赖关系分批做通，每批都能实际操作和检查：

1. **数据与统一修改入口：**房间、墙、门窗、家具数据，规则检查、撤销重做、自动保存。
2. **平面户型图：**绘制和编辑房间、墙门窗、家具。
3. **3D 展示：**全屋基座、温馨浅木风格、剖面、单间展台、点选改参数。
4. **AI 对话：**先接通 DeepSeek 并完成试看与应用，再接百炼、GLM、OpenAI。
5. **迁移与扩展：**导入导出、历史版本、简约中古风与自定义。

排序的依据是后面的功能都依赖前面的数据和修改入口：先做通一条完整链路，再增加广度。排序不等于删减，第 2 节已确定的功能仍属首版。
